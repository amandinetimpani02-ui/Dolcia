# Alertes push (offres flash) — configuration Supabase

Ce document liste ce que Claude ne peut pas faire depuis le code : créer les tables et le webhook
dans le tableau de bord Supabase. À faire une seule fois, dans l'éditeur SQL de Supabase.

## 1. Tables à créer

```sql
create table if not exists push_subscriptions (
  endpoint text primary key,
  p256dh text not null,
  auth text not null,
  latitude double precision,
  longitude double precision,
  updated_at timestamptz not null default now()
);

create table if not exists push_notifications_sent (
  offer_id bigint not null,
  endpoint text not null,
  sent_at timestamptz not null default now(),
  primary key (offer_id, endpoint)
);
```

## 2. Webhook Database → déclenchement instantané

Dans Supabase : **Database → Webhooks → Create a new webhook**

- **Table** : `flash_offers`
- **Events** : `Insert` et `Update`
- **Type** : HTTP Request
- **URL** : `https://dolcia.vercel.app/api/events?service=flash-notify` (remplacer par votre domaine réel)
- **Method** : POST
- **Headers** : ajouter `x-webhook-secret` avec exactement la même valeur que `SUPABASE_WEBHOOK_SECRET` sur Vercel

C'est ce webhook qui remplace le cron Vercel (limité à une fois par jour sur le plan Hobby, donc
inutilisable ici) : Supabase appelle directement l'endpoint dès qu'une offre passe en `status='live'`,
sans délai.

## 3. Variables d'environnement Vercel à ajouter

Voir `.env.example` : `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `SUPABASE_WEBHOOK_SECRET`.

Les clés VAPID fournies dans `.env.example` sont réelles et utilisables (générées avec le module
`crypto` natif de Node, paire EC P-256 conforme à la spécification VAPID). La clé publique est sans
risque à exposer (elle est d'ailleurs déjà dans `app.js`, comme une clé publishable Stripe) ; la clé
privée doit rester uniquement dans les variables d'environnement Vercel, jamais dans le dépôt Git.

## 4. Table pour les sessions Dolcia Anime partagées (code/QR)

```sql
create table if not exists animate_live_sessions (
  code text primary key,
  state jsonb not null default '{}',
  expires_at timestamptz not null,
  updated_at timestamptz not null default now(),
  created_at timestamptz not null default now()
);
```

Aucun webhook nécessaire ici, contrairement aux offres flash : ce n'est pas un système de
notification, juste un état partagé consulté à la demande (sondage toutes les 4 secondes côté
suiveur). Le code refuse déjà lui-même tout accès une fois `expires_at` dépassé.

## 5. Table pour les campagnes partenaires (Studio → pipeline d'envoi)

```sql
create table if not exists partner_campaigns (
  id bigint generated by default as identity primary key,
  company_name text not null,
  title text not null,
  trigger text not null,
  status text not null default 'a_controler',
  original_price numeric,
  dolcia_price numeric,
  quantity integer,
  expires_at timestamptz,
  radius_km numeric,
  latitude double precision,
  longitude double precision,
  created_at timestamptz not null default now()
);
```

Ajouter aussi `ADMIN_BRIDGE_SECRET` dans les variables Vercel (une longue chaîne que vous inventez) :
c'est ce qui protège l'endpoint d'approbation (`?service=partner-campaigns`, action `approve`) tant
qu'une vraie console d'administration avec authentification équipe n'existe pas.

## 6. Ce qui reste à décider

Une campagne approuvée dont le déclencheur est chiffrable ("place libérée", "offre flash" — avec
prix public, prix Dolcia et quantité) devient maintenant automatiquement une vraie ligne
`flash_offers`, qui déclenche le pipeline d'envoi déjà construit et déjà testé — plus besoin de
duplication. Les déclencheurs non chiffrables ("événement rare", "plan B météo") restent hors de ce
pont automatique : ce sont des formes de données différentes, forcer une correspondance aurait
fabriqué des champs (prix, stock) qui n'existent pas vraiment pour ce type d'annonce.

Ce qui manque encore : une vraie console d'approbation avec authentification équipe (`admin.html`
reste une coquille non connectée, volontairement, en attendant les rôles et le journal d'audit).
En attendant, l'approbation passe par l'endpoint protégé par `ADMIN_BRIDGE_SECRET` — un pont
manuel, pas une solution finale d'administration.
